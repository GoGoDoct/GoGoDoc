# GoGoDoc 기능 명세 (개발 참조용 요약)

원본 기획서·기능명세서 v1.4 (2026-06-15)의 핵심을 개발자가 빠르게 참조하도록 정리한 문서입니다.

## 기능 목록

| ID | 기능 | 담당                    | 요약 |
|----|------|-----------------------|------|
| F-001 | 사용자 정보 및 세션 관리 | 규진                    | 성별·나이 입력, 세션 상태 관리, 업로드 파일 메모리 처리, 개인정보 보호 문구 |
| F-002 | PDF 업로드 및 추출 | 규진                    | 업로드·유효성 검사, 디지털 PDF 확인, 표·텍스트 추출, JSON 구조화 |
| F-003 | 검사항목 정규화 및 판정 | 규진·희정                 | 항목명 표준화, 정상범위 매칭, 정상/주의/이상/응급 플래그 부여 |
| F-004 | AI 해석 및 안전 가드레일 | 희정                    | 근거 기반 쉬운 해석 생성, 단정 표현 필터, 응급 안내, 면책 강제 |
| F-005 | 결과 화면 및 추적 요약 | 석준·희정·규진              | 원본 PDF·해석 결과 Split View, 다음 검진 체크리스트 |
| F-006 | 병원 추천 및 예약 연결 (신규) | 규진·석준                 | 주의·이상 항목을 진료과목·특수장비로 매핑, HIRA 공공데이터로 근방 병원 거리순 정렬, 네이버 예약/플레이스 링크(폴백) |
| F-007 | 결과 기반 챗봇 (신규) | 석준(RAG 제외 전체)·희정(RAG) | 검진 결과 컨텍스트 자유 질문, 질문 분류로 허용 범위 제한, 공인 출처 RAG 답변, 진단·처방 질문은 전문의 상담 라우팅 |

## 파이프라인 (선형 5단계)

```
0 사용자 입력(성별·나이) → ① 파싱·추출 → ② 정상범위 매칭 → ③ 해석·설명 → ④ 안전·요약 → 화면(Split View)
부가 흐름: 결과 기반으로 F-006 병원 추천 / F-007 챗봇 응답
```

## 데이터 모델

### CheckupItem (검사 항목)
| 필드 | 타입 | 설명 |
|------|------|------|
| item_name | string | 정규화된 검사 항목명 |
| raw_name | string | 원본 PDF 추출 항목명 |
| value | number \| string | 검사 수치 |
| unit | string | 단위 |
| ref_range | string | 참조범위 원문 |
| flag | enum | 정상 / 주의 / 이상 / 응급 / 확인필요 / 알수없음 |
| explanation | string | 가드레일 통과한 쉬운 해설 |
| source | string | 해설 dict 출처 |
| track_next | boolean | 다음 검진 추적 권장 여부 |

### 해설 Dictionary
`normal_range_male/female/age`(성별·나이 정상범위), `short_desc`, `detail_desc`, `warn_desc`, `emergency_threshold {min,max}`, `icd10_codes`, `source`

### Hospital (F-006)
`hospital_name`, `address`, `latitude/longitude`, `distance_km`, `departments`(진료과목), `equipments`(CT/MRI 등 특수장비), `phone`, `reserve_url`(네이버 예약, 없으면 플레이스 폴백), `matched_reason`(추천 근거)

### ChatMessage (F-007)
`role`(user/assistant), `content`, `scope_flag`(허용: 수치설명·생활습관·진료과 / 비허용: 진단·처방·복약), `routed`(전문의 상담 라우팅 여부), `sources`(근거 출처)

## 의료 책임 경계 (가드레일)

- 모든 출력에 "참고용·진단 아님, 의료진 상담 권유" 면책 강제
- 단정 표현 금지 - "추적 관찰 권장" 형태 서술
- 응급 이상치(패닉 밸류) 감지 시 즉시 내원 안내 최우선
- 해설 dict 근거 내에서만 설명(RAG), 출처 없는 추론 차단
- F-007 챗봇은 진단·처방 질문을 전문의 상담으로 라우팅
- 개인정보: 업로드 PDF는 세션 내 처리 후 즉시 삭제, 서버 미저장

## 기술 스택

- Python, Streamlit, pdfplumber, pdf2image, Pydantic v2, rapidfuzz
- LLM: OpenAI gpt-4o-mini (파싱·해석), 임베딩 text-embedding-3-small
- 근거 검색: dict 키조회 기본 + pgvector 선택 (retriever 포트로 교체)
- DB: PostgreSQL (세션·계정, pgvector 확장)
- F-006: HIRA 공공데이터, 네이버 예약/플레이스 API

## 비기능 요구사항

- 처리 속도: PDF 1장 기준 전체 파이프라인 30초 이내
- 지원 포맷: 텍스트 레이어가 있는 디지털 PDF만
- LLM temperature: 파싱 0, 해석 0.3
- 보안: 업로드 파일 메모리 처리, 외부 저장 없음
- 항목 커버리지: 핵심 10-15개 (간수치·혈당·콜레스테롤·혈압·신장 등)

## 범위 제외

- 스캔본 OCR (디지털 PDF만)
- 다년도 결과 비교
- 서버 장기 저장
